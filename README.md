## 《月圆之夜》卡牌图鉴

这个仓库收集了《月圆之夜》游戏中经典模式和小红帽日记模式下的绝大部分卡牌，用于线上浏览和实体打印。

## 文件说明

**主要代码文件说明：**

- `card_capture.py`：用于自动化从游戏图鉴中提取卡牌贴图
- `cap1CardinGame.py`：用于手动从游戏内截取卡牌贴图

**`assets` 文件夹下各目录说明：**

- `assets_extract`：从游戏中提取的部分 unity 贴图资源
- `bookCover`：根据 tb 店铺的卡册尺寸重新排版的卡册封面
- `card_base`：经典模式图鉴中“全部”选项收录的卡牌（仅收录满星卡牌），共 696 张
- `card_base_extra`：经典模式图鉴中未出现且游戏中能遇到的部分卡牌，共 35 张
    - `egg_xxx`：彩蛋卡牌，游戏中不易遇到或通过特殊方式遇到
    - `extra_xxx`：一些卡牌/祝福的附属卡牌
    - `monster_xxx`：未出现在图鉴里的怪物卡牌
    - `newyear_xxx`：只有在春节活动中出现的活动卡牌
    - `ssr_xxx`：外婆卡组中的卡牌，出现率低或可能已被移除
    - `story_xxx`：剧情卡牌
- `card_ce`：通过 CE 修改出的部分废稿卡牌，共 83 张
- `card_ce_41`：官方愚人节动态中发布的 7 张卡牌，没想到真的做到了游戏里，通过 CE 获得
- `card_ce_ok`：卡面完整、效果完整的 CE 卡牌，共 24 张
- `card_diary`：小红帽日记模式图鉴中“全部”选项收录的卡牌，共 85 张
- `card_diary_extra`：小红帽日记模式中可以获得的 14 张初始怪物卡牌，图鉴中未出现
- `card_monster`：经典模式/小红帽日记图鉴中“怪物”选项收录的卡牌，共 149 张
- `card_skill`：部分角色的局内技能卡牌，共 17 张
- `card_upgrade`：部分相较于满星卡牌面有变化的未满星卡牌，共 48 张
- `excel`：群友通过逆向整理的卡牌信息 Excel 文件
- `kra_prjs`：使用 krita 制作的牌背文件
- `paints`：游戏中的 DLC 立绘

## 实体打印

月圆之夜的卡牌长宽比为3:2，适合使用 87x57mm 的卡牌尺寸；

经过测试，使用300g铜版纸，正面覆亮膜、背面覆哑膜的工艺效果和性价比较好

## 静态 Web 图鉴

网站使用 Vite、React 和 TypeScript，无需后端或数据库。唯一的卡牌元数据文件是 [`data/cards.json`](data/cards.json)。现有 Python 截图工具和源图片目录保持不变。

### 本地启动

需要 Node.js 22.18+ 或 24+。

```bash
npm install
npm run dev
```

打开终端显示的本地地址。启动时会先校验 JSON、检查图片是否存在，再生成列表用的 WebP 缩略图及可下载原图。新增或更换图片后，重新启动开发服务即可重新生成资源；仅修改元数据通常可直接热更新。

```bash
npm run validate  # 只检查元数据和源图片
npm test          # 检索、合并和校验逻辑测试
npm run build    # 校验、生成资源、类型检查、构建
npm run preview  # 预览构建结果
```

发布 `dist/` 即可部署到静态托管。资源使用相对地址，支持 GitHub Pages 的仓库子路径。构建只发布 JSON 引用的卡牌图片，不会把 Excel、CE 资源或整个 assets 目录打包。

### 补充卡牌数据

`cards.json` 是一个数组，每条记录代表一张卡的一个等级。例如：

```json
{
  "name": "示例卡",
  "diary": false,
  "level": 1,
  "classes": ["职业A", "职业B"],
  "type": "攻击",
  "cost": 1,
  "image": "assets/card_upgrade/示例卡1.png",
  "relatedCards": []
}
```

- `name`：完整卡名。同一模式内按名字认定卡牌身份。
- `diary`：`false` 为经典模式，`true` 为小红帽日记。两个模式都有的卡分别录入，图片可共用。
- `level`：星级正整数；没有星级时填 `null`。不要根据文件名自动推断星级。
- `classes`：可获得职业数组；暂未核实填 `[]`，不代表所有职业通用。
- `type`：类型名称不含“牌”字，例如“攻击”“装备”“法力”“咒术”，名称请统一。
- `cost`：非负整数、`"X"` 或 `null`。`0` 为明确零费，`null` 表示不适用或尚未标注；目前不区分能耗资源种类。
- `image`：仓库内 `assets/` 开头的真实图片相对路径。
- `relatedCards`：同模式下的关联卡完整名称，不需要互相引用，也不会自动递归合并所有关联。
- `hidden`：可选，默认 `false`。设为 `true` 时不占默认列表位置，仍可通过关联按钮或直接搜索其名称访问。同名各等级须保持一致。

同模式、同名、不同等级只占一个卡位。默认展示已收录的最高等级；筛选时默认展示满足条件的最高等级。切换到不满足筛选的版本会显示提示。关联卡通过当前卡位中的按钮切换，不会额外展开卡位；关联卡本身是否独立出现在列表，由其 `hidden` 决定。

**示例数据不是完整、已核实的游戏数据库。** 当前职业均留空，部分能耗为 `null`；“法力 → 小小法力”是关联切换的展示示例，不表示游戏存在直接生成关系。当前法力和机械炸药只录入了一星、二星，不代表没有更高星级。请补充、核实后再正式发布。

### 1000 张卡是否适合放在一个 JSON？

适合。每条记录即使按 1 KB 估算，1000 条也约 1 MB，压缩传输后通常更小。需要关注的是图片，不是 JSON 数组：网站每页最多展示 24 个卡位、列表使用约 360px 宽的 WebP 缩略图并懒加载，原图仅在详情或下载时请求。无需为了这个规模引入数据库。

生成目录 `public/assets/`、`public/thumbnails/` 不应手动存文件，构建时会重新生成。源图片始终维护在原始 `assets/` 下。
