## 《月圆之夜》卡牌图鉴

这个仓库收集了《月圆之夜》游戏中经典模式和小红帽日记模式下的绝大部分卡牌，用于线上浏览和实体打印。

## 文件说明

**主要代码文件说明：**

- `card_capture.py`：用于自动化从游戏图鉴中提取卡牌贴图
- `cap1CardinGame.py`：用于手动从游戏内截取卡牌贴图

**`assets` 文件夹下各目录说明：**

- `assets_extract`：从游戏中提取的部分 unity 贴图资源
- `bookCover`：根据 tb 店铺的卡册尺寸重新排版的卡册封面
- `card_base`：经典模式图鉴中“全部”选项收录的卡牌（仅收录满星卡牌），共 696 张
- `card_base_extra`：经典模式图鉴中未出现且游戏中能遇到的部分卡牌，共 35 张
    - `egg_xxx`：彩蛋卡牌，游戏中不易遇到或通过特殊方式遇到
    - `extra_xxx`：一些卡牌/祝福的附属卡牌
    - `monster_xxx`：未出现在图鉴里的怪物卡牌
    - `newyear_xxx`：只有在春节活动中出现的活动卡牌
    - `ssr_xxx`：外婆卡组中的卡牌，出现率低或可能已被移除
    - `story_xxx`：剧情卡牌
- `card_ce`：通过 CE 修改出的部分废稿卡牌，共 83 张
- `card_ce_41`：官方愚人节动态中发布的 7 张卡牌，没想到真的做到了游戏里，通过 CE 获得
- `card_ce_ok`：卡面完整、效果完整的 CE 卡牌，共 24 张
- `card_diary`：小红帽日记模式图鉴中“全部”选项收录的卡牌，共 85 张
- `card_diary_extra`：小红帽日记模式中可以获得的 14 张初始怪物卡牌，图鉴中未出现
- `card_monster`：经典模式/小红帽日记图鉴中“怪物”选项收录的卡牌，共 149 张
- `card_skill`：部分角色的局内技能卡牌，共 17 张
- `card_upgrade`：部分相较于满星卡牌面有变化的未满星卡牌，共 48 张
- `excel`：群友通过逆向整理的卡牌信息 Excel 文件
- `kra_prjs`：使用 krita 制作的牌背文件
- `paints`：游戏中的 DLC 立绘

## 实体打印

月圆之夜的卡牌长宽比为3:2，适合使用 87x57mm 的卡牌尺寸；

经过测试，使用300g铜版纸，正面覆亮膜、背面覆哑膜的工艺效果和性价比较好

## 静态 Web 图鉴

网站使用 Vite、React 和 TypeScript，浏览图鉴无需后端或数据库。卡牌元数据按源图片目录拆分到 [`data/cards/`](data/cards/) 下的 JSON 文件，现有 Python 截图工具和源图片目录保持不变。

### 按文件夹划分卡牌分组

- `data/cards/base.json` → `assets/card_base/` → `group: "base"`（经典模式）。
- `data/cards/base_extra.json` → `assets/card_base_extra/` → `group: "base_extra"`（经典附属卡）。
- `data/cards/diary.json` → `assets/card_diary/` → `group: "diary"`（小红帽日记）。

三个文件结构相同，都是记录数组；此次仅拆分原有 845 条记录，保留各组内原始顺序和元数据，没有从其他图片目录导入新卡牌。旧 `data/cards.json` 和记录中的 `diary` 布尔字段已移除。

首页自动发现 `data/cards/*.json`，显示「全部卡牌」及每个文件对应的类别。以后新增 `assets/card_<group>/` 的类别时，可添加同结构的 `data/cards/<group>.json`，或在本地编辑器中收录图片后统一保存；无需修改首页标签或加载代码。显示名称和职业模式保存在 `data/groups.json`，可通过标题旁的铅笔图标打开「分组设置」调整，不改变 group ID、目录名和卡牌 JSON 文件名。构建前会校验配置、文件名、`group`、图片目录和关联卡牌。仅扫描或在编辑列表中收录不会创建卡牌 JSON，只有最终保存才会写入。

### 分组职业模式

在本地分组设置中勾选「日记文件夹」，保存后该目录使用日记职业称呼；取消勾选恢复经典称呼。任意卡牌目录均可设置，不依赖目录名是否含 diary。现有 `diary` 组默认已启用，其他组默认经典模式。

```json
{
  "base": { "label": "经典模式", "mode": "classic" },
  "diary": { "label": "小红帽日记", "mode": "diary" },
  "custom": { "label": "其他日记目录", "mode": "diary" }
}
```

卡牌的 `group` 仍对应实际文件夹和 JSON，`classes` 始终保存统一职业值：女骑士、游侠、小女巫、药剂师、魔术师。在日记模式下分别显示小骑士、小游侠、小女巫、小药剂师、小魔术师；不会把这些显示名写回 `classes`，也不会改写已有卡牌数据。未列入映射的已有职业保留原名。

「全部卡牌」的职业筛选继续使用原统一名称；选中日记模式的分组时显示五种日记称呼，但下拉选项值、URL 筛选参数和实际检索仍使用统一值。列表、详情和跨组关联卡始终按被查看卡牌自身所属分组的模式显示。旧版分组显示名称字符串配置仍可读取（默认经典模式），保存分组设置时会为该组写入包含 label、mode 的对象。

### 本地启动

需要 Node.js 22.18+ 或 24+。

```bash
npm install
npm run dev
```

打开终端显示的本地地址。启动时会先校验 JSON、检查图片是否存在，再准备既有静态资源。开发模式的图鉴及图片管理界面直接通过受限接口读取源图，因此上传、改名或移动后刷新扫描即可预览，无须为这些操作生成图片。发布时仍由既有构建流程准备已收录卡牌的原图和 WebP 缩略图；不会批量发布未收录图片。

```bash
npm run validate  # 只检查元数据和源图片
npm test          # 检索、合并和校验逻辑测试
npm run build    # 校验、生成资源、类型检查、构建
npm run preview  # 预览构建结果
```

发布 `dist/` 即可部署到静态托管。资源使用相对地址，支持 GitHub Pages 的仓库子路径。构建只发布 JSON 引用的卡牌图片，不会把 Excel、CE 资源或整个 assets 目录打包。

### 补充卡牌数据

#### 网页编辑器

点击图鉴顶部右侧的「编辑卡牌」（`?editor`）即可编辑：

- 当前分组显示为大标题，标题旁的铅笔图标用于打开分组设置、修改显示名及「日记文件夹」选项；右侧显示当前编辑列表的已收录记录数及未收录图片数，最右侧下拉框切换目录。下一行依次为收录状态、名称搜索和紧凑上传区。新收录卡牌立即归入已收录列表，不另设“待收录”分类，是否已写入 JSON 由页面的未保存状态提示。所有已收录记录可拖动、上下移动及指定位置，最终统一保存；未填写元数据的图片不参与排序。切换组前若有未保存修改（含新卡牌），会提示确认；可先保存或导出。可用 `?editor&group=<group>` 直接打开指定组。
- 点击已收录缩略图打开窗口，可修改名称、可获得职业（经典模式 12 种，日记模式 5 种，均保存统一职业值）、星级（无、一星、二星、三星单选，分别保存为 `null`、`1`、`2`、`3`）、类型（单选）、能耗、关联卡牌及可见性。分组跟随源图片目录，在元数据表单中只读；跨组迁移需要单独执行源图片移动操作。
- 名称在离开输入框或按 Enter 时应用，仅修改当前记录；分组、名称、星级全部相同才算重复。可见性同步本组同名卡牌的所有等级。若旧名称还有其他星级，关联引用保持不变；否则会更新本组内的引用。跨文件引用不会自动改写，若导致关联失效，需先移除旧关联，完成重命名后再添加。
- 关联卡牌可以搜索所有已加载 JSON 中的卡牌并多选，不受当前文件夹限制。空输入框不展示整份卡牌列表；输入关键词后以匹配标签呈现结果，点击添加，结果标注实际目标分组。关联仍按名称存储：同名优先本组，再优先保留原有经典 / 附属卡关系，否则按固定分组顺序定位到一个分组，不混合不同分组的星级。保存校验、图鉴关联切换和文件移动检查使用相同规则。
- 使用 `npm run dev` 点击「保存到本地 JSON」，只写入运行开发服务的机器上当前分组的 `data/cards/<group>.json`，不会覆盖其他组的文件或顺序。支持本机、局域网和 OpenChamber 预览代理访问。接口通过临时令牌保护写入，禁止跨站请求及跨域读取令牌；生产构建不包含写文件服务。开发服务没有登录权限控制，请勿暴露到不可信网络或公网。
- 静态网站和 `npm run preview` 仅提供「导出 JSON」，下载当前组的 `<group>.json` 后替换 `data/cards/` 下的同名文件，再重新构建部署。
- 保存/导出前校验元数据、重复星级和关联卡牌。文件被其他程序修改时拒绝覆盖，可先导出当前编辑作为备份，再重新载入。
- 普通元数据修改及新卡牌收录均先留在当前组草稿中，点击「保存到本地 JSON」才统一写入，离开时会提示。可以连续收录多张图片，并继续修改、排序、关联或导出备份。文件改名、移动、上传和分组设置仍是立即执行的独立操作，后台保留冲突检查和备份；当前组有未保存草稿时需先保存，避免文件操作刷新列表而丢失草稿。
- **删除已收录记录**：打开卡牌编辑窗口，点击「删除已收录记录」并确认，仅移除当前这条元数据记录，不删除源图片、同名其他星级或其他编辑。删除先留在草稿中，统一保存后才写入当前组 JSON；静态模式通过导出 JSON 生效。最后一条记录也可删除，保留空数组文件。若删除会使其他卡牌关联失效，需先移除对应关联；后台保存时会再次校验所有分组。源图不再被任何当前记录引用时，会显示在「未收录图片」中，可重新收录；缺失的源图不会被当作可收录图片。刷新扫描或切换组时确认丢弃，可放弃未保存的删除。

#### 本地图片管理

仅 `npm run dev` 提供本地文件管理功能。操作的是**运行开发服务的机器**上的仓库文件，静态部署或 `npm run preview` 不具备扫描硬盘、持久上传或改写源文件的接口。

- **刷新扫描**：只读取 `assets/card_*/` 中的 PNG、JPEG、WebP，排除符号链接和其他资料目录。既有 JSON 之外的卡牌目录也可浏览，但不会自动创建它们的元数据文件。
- **状态筛选**：「全部图片」「已收录」「未收录」「源图缺失」。刚收录但尚未保存的新卡牌也属于当前编辑列表的“已收录”。未收录卡面使用 CSS 灰度和透明遮罩，不会生成灰色版、未收录缩略图，也不会加工源文件。`hidden` 只决定卡牌在图鉴中的可见性，与收录状态不同。
- **统一保存的收录**：点击未收录图片 →「填写元数据，收录卡牌」→ 手动选择类型、核对星级等字段 →「收录卡牌」。此时只追加到已收录编辑列表，不写文件、不刷新页面，也不改变当前状态筛选或名称搜索；例如在“未收录”视图连续收录时，图片逐一移出该视图，可继续处理剩余图片。可以继续编辑、排序，或在卡牌窗口「撤销本次收录」，不删除源图或丢弃其他修改。卡名仅按文件名预填，不会自动推断星级、职业、类型或 OCR 入库。最后「保存到本地 JSON」将新卡牌、已有元数据修改及排序一次写入；该组尚无 JSON 时也只在最终保存时创建。任何一条校验失败都不部分写入，未保存修改仍保留。手动刷新或切换组并确认丢弃，会放弃尚未保存的修改。
- **源图片改名**：从图片管理窗口修改物理文件名，保留扩展名；同步所有引用该图片的 `image` 字段，不修改卡牌 `name`。已收录卡牌可在编辑窗口点击「管理源图片文件」进入。
- **删除源图片**：源图片管理窗口提供删除按钮，执行前会保存原始字节备份。仅删除图片文件，不自动删除任何卡牌元数据或关联；已收录图片删除后会标注缺图，需恢复同名图片或手动处理元数据后再构建发布。未收录图片删除不修改或创建 JSON。文件操作仍需先保存当前元数据修改，避免丢弃编辑内容。
- **跨文件夹移动**：未收录图片只移动文件，不创建 JSON；已收录图片会迁移全部引用记录，更新 `group` 和 `image`，追加到目标组末尾。禁止同名文件覆盖、重复身份或产生失效关联，不会擅自删除关联。需要先修正冲突关系再重试。
- **本地上传**：选择目标目录后选文件或拖入上传区，原始字节保存在该目录，先作为未收录图片，不自动生成元数据。支持 PNG、JPEG、WebP，并校验实际内容；一次最多 20 张，单张不超过 20 MB、4000 万像素，总计不超过 40 MB。同名文件应先改名，不会自动覆盖。
- **缺失源图**：保留 JSON 记录并显示警告，不会静默删除元数据。恢复源文件后刷新扫描；缺失图片不能重命名、移动或再次收录。
- **分组设置**：点击当前分组标题旁的铅笔图标，可编辑显示名和「日记文件夹」选项；保存到 `data/groups.json`，不改内部 group ID、目录名或卡牌职业原值。静态网站使用已构建的配置，修改持久配置需运行 `npm run dev`。

文件操作有版本校验、预检查、临时写入和备份日志；多文件操作失败会尝试回滚，开发服务启动时会恢复未完成的事务。备份保存在被 Git 忽略且禁止经开发服务器访问的 `.card-editor/transactions/`，可能包含源文件原始字节。若外部改动阻止恢复，会明确报错并拒绝覆盖；请保留日志和原文件，人工核对后再恢复操作，不要通过删除未完成日志来绕过保护。已完成的备份不会自动删除，请按需要自行归档。

开发服务没有用户账号和权限隔离，临时令牌与跨站保护不是公网鉴权，请勿暴露到不可信网络。同一仓库只使用一个开发服务执行文件写入，不要同时运行多个写入服务。

每组 JSON 都是一个数组，每条记录代表一张卡的一个等级。例如 `base.json` 中的一条记录：

```json
{
  "name": "示例卡",
  "group": "base",
  "level": 1,
  "classes": ["职业A", "职业B"],
  "type": "攻击",
  "cost": 1,
  "image": "assets/card_base/示例卡1.png",
  "relatedCards": []
}
```

- `name`：完整卡名。同一分组内按名字合并卡牌等级。
- `group`：字符串，必须与所在 JSON 文件名一致，例如 `base`、`base_extra`、`diary`。不再使用 `diary` 布尔值。
- `level`：星级正整数；没有星级时填 `null`。不要根据文件名自动推断星级。
- `classes`：统一职业值数组（如 `女骑士`、`游侠`）；日记显示名由分组模式映射，不另存一套职业字段。暂未核实填 `[]`，不代表所有职业通用。
- `type`：类型名称不含“牌”字，例如“攻击”“装备”“法力”“咒术”，名称请统一。
- `cost`：非负整数、`"X"` 或 `null`。`0` 为明确零费，`null` 表示不适用或尚未标注；目前不区分能耗资源种类。
- `image`：当前组的 `assets/card_<group>/` 目录下的真实图片相对路径。
- `relatedCards`：任意已加载 JSON 或当前组新收录卡牌中的完整名称，允许跨分组关联；目标必须已有元数据，不能引用仅扫描到的图片。本次新收录卡牌可互相关联，统一保存时一起校验写入。不需要互相引用，也不会递归展开关系链。
- `hidden`：可选，默认 `false`。设为 `true` 时不出现在图鉴列表和名称搜索中，仍可通过关联按钮访问。同名各等级须保持一致。

同分组、同名、不同等级只占一个卡位，不同分组不会合并。默认展示已收录的最高等级；筛选时默认展示满足条件的最高等级。切换到不满足筛选的版本会显示提示。关联卡通过当前卡位中的按钮切换，不会额外展开卡位；关联卡本身是否独立出现在列表，由其 `hidden` 决定。

**收录数据仍需核实。** 部分职业、能耗和关联关系可能尚未补齐，请根据游戏资料逐步维护；关联按钮不代表已核实的游戏生成关系。

### 1000 张卡是否适合放在一个 JSON？

适合。每条记录即使按 1 KB 估算，1000 条也约 1 MB，压缩传输后通常更小。需要关注的是图片，不是 JSON 数组：静态网站单页展示全部筛选结果，列表使用约 360px 宽的 WebP 缩略图并懒加载；本地管理模式直接读取源图并懒加载，不生成未收录缩略图。无需为了这个规模引入数据库。

生成目录 `public/assets/`、`public/thumbnails/` 不应手动存文件，构建时会重新生成。源图片始终维护在原始 `assets/` 下。
